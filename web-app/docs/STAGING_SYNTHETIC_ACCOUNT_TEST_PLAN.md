# Staging synthetic account preparation

This document is for a non-production MongoDB Atlas database containing **synthetic records only**. Never use real student identities, passwords, grades or transcripts. Do not commit credentials.

## Proposed test identities (not yet provisioned)

| Role | Identifier | Student ID | Purpose |
| --- | --- | --- | --- |
| STUDENT | demo.student.2028 | DEMO-2028-001 | Student-scoped provisional preview |
| ADMIN | demo.admin | none | Read-only curriculum catalogue and role isolation |

Both identities are fictional. Use unique random passwords generated by an operator, store only Argon2 hashes in the `users` collection, and keep passwords in an approved secret manager. Set `forcePasswordChange: false` **only** for these isolated, temporary synthetic demo accounts, since the current frontend cannot perform password changes. Remove the accounts after testing.

Do not provision these accounts until the operator confirms that `MONGODB_URI` points to the isolated `ashesi_graduation_staging` database and has verified the deployment. No account should be created in a real student database.

## Test matrix

1. Open the staging website and verify that its HTML loads.
2. Open `https://ashesi-tracker-api-staging.onrender.com/health`; expect HTTP 200 and `{"status":"ok"}`.
3. From the staging frontend origin, test login with a synthetic student account; expect CORS to allow the configured origin.
4. Test student academic preview with only the matching synthetic student record.
5. Verify a student token cannot access `/api/v1/admin/curricula` (403).
6. Verify an admin token cannot access `/api/v1/students/me/academic-preview` (403).
7. Verify unauthenticated access to both protected routes returns 401.
8. Verify curriculum review remains disabled (`ENABLE_CURRICULUM_REVIEW=no`) and no official graduation certification is returned.

The above checks are a plan, not evidence that accounts exist or that the tests have passed.
